# 顶部“阶段 ↔ 节点”视觉方案（V1.0 待确认稿）

## 1. 现状问题

1. 阶段页签与下方节点没有视觉对应关系（页签是独立一行，节点是另一行，看不出哪个节点属于哪个阶段）；
2. 节点下的小字（班组级/运行部级/公司级…）与阶段名重复，信息冗余且挤压空间导致重叠；
3. 9 个节点在窄屏放不下，强行排布产生遮挡；
4. 后续节点可能继续增加，当前布局不可扩展。

## 2. 设计目标

- 一眼看出“当前在哪个阶段、这个阶段包含哪些节点、前后还有哪些阶段”；
- 不挤、不重叠，窄屏可横向滑动；
- 信息最少化：节点只保留“序号 + 名称 + ?（处置指导）”；
- 支持后续节点增加而不破坏整体结构。

---

## 3. 方案 A（推荐）：阶段分区轨道

### 结构

```
┌──────────────┬─────┬─────┬─────┬──────────────┐
│ ● 班组处置    │ ● 运行部级 │ ● 公司级 │ ● 政府级 │ ● 收尾阶段   │  ← 阶段头（按节点数占比宽度）
├──────────────┼─────┼─────┼─────┼──────────────┤
│ ① ② ③ ④    │ ⑤  │ ⑥  │ ⑦  │ ⑧ ⑨        │  ← 节点画在所属阶段分区内
└──────────────┴─────┴─────┴─────┴──────────────┘
```

- 5 个阶段分区横向排列，宽度按节点数比例（班组处置 4/9、运行部级 1/9、公司级 1/9、政府级 1/9、收尾 2/9）；
- 每个分区顶部是阶段头（圆点 + 阶段名，去掉“1-4/5-5”范围），下方分区内放置该阶段节点；
- 阶段与节点天然对应：节点画在所属分区内部，分区之间用浅色分隔线；
- 颜色沿用：蓝/青/金/红/绿。

### 聚焦策略（解决放不下）

- 默认只展开“当前阶段 + 前 1 个阶段 + 后 1 个阶段”的节点；
- 其他阶段显示为“收起圆点 + 阶段名”，点击后再展开该阶段；
- 顶部整块支持横向滚动，后续节点增加时分区内部继续排布。

### 节点内容（信息最少化）

- 每个节点只显示：序号圆点（完成打勾 / 进行中脉冲）+ 节点名称 + ?（处置指导）；
- 删除节点下的“班组级/运行部级/公司级…”小字；
- 删除阶段页签上的“1-4/5-5”范围。

### 与 L2/L3 联动

- 点击阶段分区 → L2 切换为该阶段的“详情与指挥内容”；
- 点击节点 → 指挥卡聚焦到该节点，并联动地图；
- L3 详情弹窗保持不变（全矩阵 + 管理）。

---

## 4. 方案 B：单轨聚焦（备选）

- 一条水平时间线，只渲染当前阶段 + 前后各 1 个阶段的节点，其余阶段用圆点占位；
- 当前阶段以胶囊标签浮在时间线上方；
- 更简洁，但“阶段分区感”较弱，多个相邻阶段展开时仍可能拥挤。

## 5. 方案 C：阶段卡片横向堆叠（备选）

- 每个阶段一张横向卡片，卡片内放节点，卡片之间可横向滑动；
- 分区感最强、扩展性最好，但整体高度更高，占用地图空间更多。

## 6. 示例实现与验收

> 2026-08-13：定稿采用 **方案 A（阶段分区轨道）**，并叠加“渐进式解锁”：
>
> - 初始只呈现“班组处置 + 收尾阶段”；
> - 班组处置（节点 1-4）必执行完成后，可在阶段末决策“升级到运行部级 / 直接收尾”；
> - 确认升级后该阶段才逐级出现（运行部级 → 公司级 → 政府级），未确认的阶段完全隐藏；
> - 班组完成后“直接收尾”按钮随时可用；升级需当前阶段全部节点完成。

建议最终采用 **方案 A**：阶段分区轨道 + 当前±2 阶段聚焦 + 信息最少化。

## 8. 流程交互设计（升级/收尾决策，已定稿）

- 班组处置为必经流程（节点 1-4）；
- 班组处置完成后弹出决策：**直接收尾** 或 **升级到运行部级应急**；
- 运行部级/公司级完成后同样弹出决策：**直接收尾** 或 **升级到下一级**；
- 政府级完成后自动进入收尾阶段；
- 任意级别选择“直接收尾”即跳转收尾阶段（应急终止 → 总结评估与恢复）；
- 运行部级/公司级/政府级各 3 个节点（当前命名“节点1/2/3”）。

### 业务规则（渐进式呈现）

1. 班组处置为必经流程，节点 1-4 全部完成后才算完成；
2. 班组完成后：阶段末弹出决策“升级到运行部级 / 直接收尾”；顶部“✅ 直接收尾”按钮同时可用；
3. 升级需当前阶段全部节点完成，未完成时决策弹窗中“升级”按钮禁用并提示；
4. 确认升级后，下一阶段分区才出现（未确认阶段隐藏，不可点击）；
5. 政府级完成后自动进入收尾阶段，流程结束。
