## 1. 现状问题

当前 UI-project 中间“预案全景全流程”模块基本是**静态展示**：

- 处置流程全景：阶段节点仅“进行中”阶段有子任务下拉，节点本身不可点击、无联动；
- 全流程矩阵：动作卡不可点击（视觉上是按钮，但没有绑定任何交互），无详情、无状态切换；
- 只有“展开预案矩阵”按钮可用，交互全部集中在全屏弹窗里，演示时中间模块“看着热闹、点不了”。

mm-safety-master 的对应模块（应急流程 + 处置过程指导）是**强交互**的：节点点击联动、问号处置指导、响应级别切换、节点配置、动作卡状态流转等。

## 3. 目标交互方案（推荐）

### 3.1 处置流程全景（时间轴）

1. **节点可点击**：点击阶段节点 → 激活该阶段，矩阵自动聚焦到该阶段（focus 模式），地图飞至对应装置区（复用现有 `flyToWorldPositions`）。
2. **问号处置指导**：每个节点右侧“?”→ 居中浮窗，内容按 safety-master 结构：当前值班表、汇报关系链（谁向谁汇报、用什么方式、汇报要点）、各岗位处置任务清单（勾选项）、安全注意事项。
3. **响应级别下拉**：班组处置 → 装置区应急 → 全厂应急 → 政府应急；切换时弹出升级确认，确认后时间轴跳至对应节点、矩阵切换对应预案/阶段。
4. **节点配置（演示级）**：齿轮按钮弹出当前节点联动配置面板，只读展示 3D 地图视角、右侧面板 Tab、左侧卡片、值班岗位；允许开关显隐并即时生效，但不持久化编辑。
5. **子任务下拉**：保留现有“进行中阶段展开子任务”能力。

### 3.2 全流程矩阵

1. **动作卡可点击**：中间模块与全屏弹窗的卡片统一行为——点击打开详情（标题、所属大阶段、绑定范围、责任力量、应到/实到、负责人/电话、关联风险、处置规程要点、安全要求），支持三态切换（待执行/执行中/已完成）。
2. **hover 反馈**：卡片 hover 高亮边框 + 上浮 + “查看详情”提示，明确可点。
3. **状态全局联动**：单卡片状态变化后自动重算：
   - 阶段内全部卡片已完成 → 时间轴节点“已完成”；
   - 有任一卡片执行中 → 节点“进行中”；
   - 否则 → “未开始”；
   - 阶段百分比 = 卡片完成占比（或沿用子阶段进度加权）。
4. **切换预案**：保留弹窗内切换；中间模块增加预案下拉（可选）。

### 3.3 全局状态与数据

- 新增 `useEmergencyProcess` 状态：`activePhaseId`、`responseMode`、`completedPhases`、节点指导数据（移植 safety-master `emergencyProcessData` / `nodeGuidanceData`）。
- 与现有 `usePlanMatrix` 打通：矩阵卡片状态 → 阶段进度 → 时间轴状态；时间轴激活阶段 → 矩阵 focus。
- 数据统一放 `src/lib/data/`（TS interface），组件不硬编码。

### 3.4 演示推进

- 模块顶部提供“下一步”按钮：把当前阶段所有待执行卡片批量置为“执行中”（或“已完成”），演示时可按“接警研判 → 能量隔离 → 退守稳态 → …”一口气讲完完整流程。
- 可选“自动演示”模式：每 3~5 秒自动推进一个阶段，配合讲解。

## 4. 交互深度分级（供选择）

| 级别                    | 内容                                                                              | 工作量 |
| ----------------------- | --------------------------------------------------------------------------------- | ------ |
| L1 基础交互（推荐必做） | 节点点击聚焦、?处置指导、卡片点击详情+状态切换、状态全局联动、一键推进            | 中     |
| L2 演示增强（推荐）     | 响应级别切换+升级确认、节点配置只读弹窗、中间模块预案下拉、列宽拖拽               | 中     |
| L3 完整复刻             | 右键新增/编辑/删除阶段/组织/风险/动作卡、节点配置可编辑持久化、流程飞线、五维面板 | 大     |

建议本次做到 **L1 + L2**，L3 按客户演示重点选择性加入。
