## 2. P0 重大偏差

### 2.1 移动端技术形态：Android 原生 vs Vue H5

- **详设 V1.5（§5.3）**：移动端定义为 **Android Kotlin 原生应用**（`mobile.app` 命名空间），文件清单为 `location/BeidouLocationService.kt`（北斗无感定位）、`database/OfflineCacheDatabase.kt`（SQLite 离线库 + AES-256 加密）、`sync/OfflineDataSyncWorker.kt`（后台静默补发）等原生组件；§5.3.2 实现框架明确 Kotlin。
- **当前项目**：移动端规划为 Vue 3 H5（`apps/mobile` 独立入口、`[data-theme='mobile']`、`useOfflineOutbox.ts` 离线缓存），UI 规范文档已按 H5 产出。
- **影响**：`apps/mobile` 尚未开工，暂无返工；但**在开工前必须决策**：
  - 方案 A（按详设）：原生 APP 承载定位/离线/推送，H5 可作为内嵌页面层（hybrid），现有 token 体系与 UI 规范继续用于 H5 部分；
  - 方案 B（偏离详设）：坚持纯 H5，需与设计方书面确认北斗后台定位、SQLite 加密离线、系统级推送在 H5 上的替代方案（能力上有客观差距）。
- **建议**：倾向 A（hybrid），原生壳 + Vue H5 业务页，`useOfflineOutbox` 与 UI 规范均不报废。

## 4. P1 规范修订（详设 vs UI 规范文档 / AGENTS.md）

1. **触控热区 48–56px（§3.4）**：详设要求移动端可点元素物理高度**严格控制在 48px 至 56px 之间**。当前 `AGENTS.md` 写的是 ≥44px，`UI规范-移动端.md` 主按钮 `--mb-btn-h: 44px`。→ 以详设为准修订：主按钮上调至 48，全部热区下限 48、上限 56。
2. **户外强光模式重新定义（§3.4）**：详设的户外方案是**可切换的"高反差单色皮肤"**（mobile-flat）：纯白 `#FFFFFF` 底 + 纯黑 `#000000` 字，**停用一切渐变/软投影/毛玻璃/浅灰装饰线**，WCAG AAA（>7:1）；状态标签**取消浅底描边样式，改为高饱和纯色色块填充 + 高对比硬描边**。当前 `UI规范-移动端.md` 把户外高对比写成了常规态要求（浅底同色标签 + 主色实色按钮）。→ 改写为「常规态（现规范）+ 强光皮肤模式（详设黑白高反差）」双层结构。
3. **大字模式细则（§3.4）**：大字下核心字段**不作截断、自适应换行**，行高弹升至 **1.8 倍字号**。当前适老章节只写了字号档位和行高值。→ 补充。
4. **Logo 交互（§3.4）**：Logo 置左上角、**点击返回主页**。`apps/mgmt` 壳层品牌区当前是纯文本。→ 补链接交互（大屏顶栏同步确认）。
5. **表格隔行变色（§3.4）**：详设推荐表格**隔行变色**（战时高压阅读）。当前后台表格为白底行 + 细分隔线。→ `mgmt.css` 补 `el-table` 斑马纹（`--el-fill-color-lighter` 走 token），UI 规范后台文档同步。

**已符合、无需改**：默认字体微软雅黑（`--font-family-zh` 首选即 Microsoft YaHei ✓）；2 空格缩进（prettier tabWidth:2 ✓）；`<!DOCTYPE html>` + utf-8 ✓；移动端纯单列卡片流、一屏一个实心胶囊主按钮、次按钮白底描边 ✓（与 §3.4 完全一致）。

**间距/字号说明**：§3.4 引用《石化智云 UI 规范》"推荐外边距 16、内边距 24、标题 16、正文 14"，但同时注明"可按分辨率及视距动态适配"。端规范细化的页标题 28 / 页边距 24 属于该授权范围内的适配值，**不构成硬偏差**，但建议在 UI 规范文档中显式注明与石化智云基线的换算关系，便于验收对账。

## 5. 已对齐项（详设要求 = 项目现状）

1. API 风格：RESTful + JSON + `/v1` 前缀（http.ts `baseURL=/api/v1`；端路径 `/v1/screen|admin|mobile` 规划一致）。
2. 鉴权：JWT `Authorization: Bearer` 内存态令牌，禁 localStorage 明文（token.ts/http.ts ✓，与 §4.2.7 B 域本地验签模型吻合）。
3. 硬反控安全：http.ts 已有 `guardHardControl` 拦截（消防水泵/灭火设施只读监测、严禁下行的红线在代码层有闸）。
4. 三端形态与主题挂载：大屏深色科技蓝（`:root`）、后台/移动白底（`data-theme`）与 §3.4 配色总原则一致。
5. 移动端单列卡片流、一屏单主行动、适老一键切换（§3.4 与 UI规范-移动端.md 一致）。
6. 代码规范：2 空格、utf-8、DOCTYPE、Chrome/Edge 兼容（§3.5 ✓）。
7. 离线缓存思路：详设移动端"断网缓存、重连静默补发"与 `useOfflineOutbox.ts` 语义一致（实现载体待 §2.1 决策）。
8. 大屏 WebSocket 订阅警情：详设 §5.1.7 与现有 `ws.ts`/realtime 服务一致。
9. 等保二级"敏感操作审计留痕 ≥6 个月"：前端审计埋点已有 `services/audit.ts` 雏形（留痕主体在后端，前端无冲突）。
10. 大屏性能工程：详设 SLA/渲染要求与 `docs/perf/` 基线、`utils/perf-budget.ts` 机制方向一致（数值需对账，见 §7）。
