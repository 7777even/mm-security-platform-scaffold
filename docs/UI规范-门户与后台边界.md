# UI 规范 — 门户（大屏态势）与后台管理边界

> 跨端红线补充：明确「门户 / 大屏态势」与「后台管理」两类界面的视觉与容器边界，禁止互相越界。
> 三端视觉语言总则见各端 `docs/UI规范-*.md`；本文件处理端间边界。

## 边界总则

- **门户 / 大屏态势**：科技深蓝、玻璃质感、发光、渐变、大屏数据列表；面向态势感知。
- **后台管理**：浅色白卡、浅底标签、实色按钮、表单密集；面向运维操作。
- 两者**视觉语言不得混用**，否则破坏品牌一致性与高压可读性（AGENTS.md §6.4）。

## 禁止项（硬约束）

| 场景     | 禁止                                                                      | 落点              |
| -------- | ------------------------------------------------------------------------- | ----------------- |
| 大屏态势 | 出现后台白底卡片 / 浅灰页面底 / `#0b69d7` / `#1677ff` / `.tag-*` 浅底标签 | 大屏规范 §6.4     |
| 后台管理 | 出现玻璃质感（`--glass-*`）/ 科技青 `#00d8ff` / 发光边框 / 深蓝黑底       | 后台规范 §6.4     |
| 门户界面 | 使用 `admin-*` 容器（管理后台专属布局组件）                               | training 规范对齐 |
| 管理后台 | 使用门户学习卡片 / 态势专属组件                                           | training 规范对齐 |

## 落地要求

- 新增页面先判定归属「门户」或「后台」，再套用对应端规范与 token。
- 跨端复用组件（如 `.tag-*` 状态标签）须用 token 自然区分，不得硬编码端特异分支。
- 疑似越界时回到各端 `docs/UI规范-*.md` 与本文件仲裁（根 `AGENTS.md` 高于分层文件）。
