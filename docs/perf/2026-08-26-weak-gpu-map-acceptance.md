# 弱 GPU 地图渲染验收报告（D1 P7–P10 配套真机复测）

> 配套 `harden-d1-frontend-baseline` 的性能预算（`src/utils/perf-budget.ts`：P7 进入平台 ≤5s / P8 功能窗口 ≤2s / P9 基础地图 ≤2s / P10 部件查询 ≤2s）。
> 本报告针对基线报告 `2026-08-18-performance-baseline.md` §4.2 / §6 标记的「⚠️ 渲染层 ⚠️ 待真机复测」项，补强**弱 GPU（石化窗 Chromium 86 / 海光 C86 / 麒麟 V10）地图平移/缩放流畅度**证据。

## 0. 度量口径说明（重要）

- **P7–P10 度量的是「耗时」**：进入平台 / 窗口切换 / 地图初始化 / 查询响应，由 `main.ts`/`router`/`cesium.ts`/`useAlarmView.ts` 的 `recordPerf*` 埋点采集，阈值见 `perf-budget.ts`。
- **本轮度量的是「交互帧率 FPS」**：地图拖拽/缩放时主线程与 Cesium 出图的真实帧率，属**渲染层流畅度**，是 P9「基础地图 ≤2s 可用」体验成立的**前提兜底**，二者互补而非替代。
- FPS 非 P 档硬预算，列为 G1 弱 GPU **体验观测项**；P9 的**耗时**读数仍需按 SOP §6.2 在真机冷启动回填（见 §5.3）。

## 1. 优化项清单（commit `5ce263f`，`src/services/cesium.ts`）

针对弱 GPU 每帧 GPU 绘制成本（瓶颈判定见 §3），逐项削减：

| 优化项                                       | 默认值 → 现值                                             | 作用                                         |
| -------------------------------------------- | --------------------------------------------------------- | -------------------------------------------- |
| `resolutionScale`                            | 1.0 → **0.6**（可由 `VITE_CESIUM_RESOLUTION_SCALE` 覆盖） | 帧缓冲降采样，片元量 ↓约 64%                 |
| `scene.msaaSamples`                          | 4 → **0**                                                 | 关多重采样，每帧片元着色 ↓至 1/4             |
| `postProcessStages.fxaa`                     | 开 → **关**                                               | 关全屏后处理抗锯齿 pass                      |
| `scene.skyAtmosphere`                        | 开 → **关**                                               | 关全屏逐片元大气散射（卡顿主因之一）         |
| `scene.sun`                                  | 开 → **关**                                               | 关太阳光照逐片元计算                         |
| `globe.maximumScreenSpaceError`              | 2 → **8**                                                 | 瓦片更粗糙，平移时请求/解码/绘制量 ↓         |
| `globe.preloadAncestors` / `preloadSiblings` | 开 → **关**                                               | 关无关祖先/兄弟瓦片预拉，降主线程与 GPU 抖动 |
| `globe.showGroundAtmosphere`                 | 开 → **关**                                               | 关地面大气辉光片元计算                       |

> 既有不变量：`requestRenderMode=true`（空闲近乎零渲染）、`shouldAnimate=false`（时钟不走时）、`fog.enabled=false`、`skyBox/baseLayer` 置空（零下行红线）均保留。

## 2. 复测手段

- 临时 FPS 诊断浮层（`?perf=1` / DEV 下显示，已提交后移除）：独立 rAF 循环测主线程帧率 `raf`，`scene.postRender` 计 Cesium 出图帧率 `render`，`camera.moveStart/End` 分段统计 `active`（交互）/ `idle`（空闲）/ `minActive`（交互最低）。
- 判定逻辑：`raf==render` 且双低 → 瓶颈为每帧同步 WebGL 绘制（GPU），非 JS 阻塞；据此定向削减片元开销。

## 3. 真机读数（按 SOP §6，`?perf=1`）

| 阶段                                           | raf   | render | active | minActive | 说明                                |
| ---------------------------------------------- | ----- | ------ | ------ | --------- | ----------------------------------- |
| 基线（优化前）                                 | 9     | 9      | 9      | 7         | 拖拽时主线程被同步绘制吃满，9fps    |
| 第一轮（skyAtmosphere/maxSSE/preload/res 0.7） | 13–21 | 13–21  | 13–21  | 6         | 帧率提升，但仍受 GPU 每帧绘制限制   |
| 第二轮（msaa0/fxaa/sun/res 0.6）               | —     | —      | —      | —         | **未复测**（用户确认停止，见 §5.2） |

读数印证瓶颈为**每帧 GPU 绘制成本**（交互时 `raf==render` 完全同步），故本轮全部针对片元/瓦片降负，方向正确。

## 4. 与 P7–P10 预算对应关系

| 预算             | 受影响？ | 结论                                                                                                                                              |
| ---------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| P7 进入平台 ≤5s  | 否       | 渲染降负降低首屏 GPU 负担，对进入耗时无负面影响                                                                                                   |
| P8 功能窗口 ≤2s  | 否       | 不涉地图渲染                                                                                                                                      |
| P9 基础地图 ≤2s  | 间接正向 | 地图初始化打点（`cesium.ts:322` / `BaseMap.vue:177`）；降负不增加初始化耗时，且令 P9「地图可用」在弱 GPU 上体验成立。**真机耗时读数待 §5.3 回填** |
| P10 部件查询 ≤2s | 否       | 不涉地图渲染                                                                                                                                      |

## 5. 结论与遗留

### 5.1 已闭环

- 弱 GPU 地图渲染降负已入库（`5ce263f`），开启 `requestRenderMode` + 削减全屏片元/瓦片开销，平移/缩放帧率较基线 9fps 提升至 **13–21fps**（第一轮实测）。
- D1 性能预算「声明+度量能力」层面已完成（`perf-budget.ts` + 各模块埋点），本报告补强了**弱 GPU 体验证据层**。

### 5.2 遗留（第二轮未复测）

- 第二轮（MSAA/FXAA/太阳光照/`resolutionScale 0.6`）逻辑上进一步削减每帧片元约 4×，但**未做真机读数确认**。
- 建议在目标机器（石化窗 Chromium 86 / 海光 C86）补一轮 `?perf=1` 拖拽/缩放读数，确认是否达 ≥30fps 体验目标；若仍未达，按 SOP §6.2 越界处理（骨架屏/路由级代码分割已具备），或评估点位聚合降采样。

### 5.3 P9 真机耗时读数待回填

- P9 `baseMapMs` 的**真机冷启动耗时**尚未在 G1 环境实测（受限于本环境无信创真机）。
- 待 G1 到位后按 `2026-08-18-performance-baseline.md` §6.2 冷启动测量 `[perf] baseMapMs`，回填至该基线报告 §4.2，完成 D1 性能项全闭环。

### 5.4 环境约束（已声明）

- 本环境无信创真机，浏览器级 FPS 压测与 P9 真机耗时为 CI-browser / G1 步骤，不在提交范围内（符合 `harden-d1-frontend-baseline` 非目标声明）。
