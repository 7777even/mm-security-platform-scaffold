# engineering/ — 研发过程记录

存放**短期、一次性**的研发过程记录，与长期知识库 `docs/` 严格分离。文件命名统一 `YYYY-MM-DD-<kebab-slug>.md`。

## 五个子目录

| 目录       | 记什么                                                                 | 何时写                   |
| ---------- | ---------------------------------------------------------------------- | ------------------------ |
| `plans/`   | 推进计划、里程碑台账、阶段性排期                                       | 排期确定或调整时         |
| `qa/`      | 验证过程与结果：范围、验收口径、实际命令与用例数、未运行项、结论、证据 | L3 / L4 交付前必写       |
| `retro/`   | 复盘：做得好、问题、原因、改进方案                                     | L3 / L4 收尾、故障复盘时 |
| `ship/`    | 发布检查与回滚方案（上线前逐项确认）                                   | 每次进共享环境前         |
| `reports/` | 面向干系人的阶段简报（对照 roadmap 判据、用证据说话）                  | 每个路线图阶段收口时     |

> `reports/` 面向干系人，`qa/`+`retro/` 面向工程内部——三者不要互相顶替。用法见 `reports/README.md`。

L0 / L1 / L2 改动默认不写这些记录。

## 三条纪律

1. **不写第二套任务**：目录里只记状态和证据，实施任务永远以 `openspec/changes/<name>/tasks.md` 为准，不得在本目录另立任务清单。
2. **报告实际执行的命令**：写清跑了什么（`npm run type-check` / `vitest run` / `gate:screen` / `validate-api-contracts.mjs` / `build:subapps`）、通过多少、哪些没跑（例如构建因环境限制未执行），禁止用无关的全量命令冒充目标验证，也禁止把未执行写成通过。
3. **临时产物不放这里**：构建日志、lint 输出、diff 快照等一次性产物用完即删，不入库（提交规范见根 `AGENTS.md` §6）。

## 模板

- QA / Retro 内容：从 `../templates/_qa_template.md` 与 `../templates/_retro_template.md` 复制填充。
- 发布检查：从 `../templates/_ship_template.md` 复制填充（若本库无该模板，用后端库同款）。
- 阶段汇报（向甲方 / 团队汇报）：从 `../templates/_stage_report_template.md` 复制填充。
